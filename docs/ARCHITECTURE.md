# Architecture

Cordon is a privacy pool for tokenized stocks (Robinhood Stock Tokens, ERC-8056) on
Robinhood Chain. Users hold **notes**: commitments in one Merkle tree that name an
asset, an amount, an owner key and a class. Notes can be split into claims (PRINCIPAL,
INCOME, VOTE, REDEEM, CONTROL), sent privately, pledged, traded atomically (DvP), and
withdrawn. Every note spend carries a zero-knowledge proof (Noir, UltraHonk) that the
contracts verify on-chain.

## Components

| Component | Where | Role |
|---|---|---|
| Circuits | `circuits/` (Noir 1.0.0-beta.22, bb 5.0.0-nightly.20260522) | transfer, bundle, unbundle, term, income, encumber, unlock, enforce, order, dvp, nav |
| Verifiers | `contracts/src/verifiers/` | Generated by `circuits/build.sh`; CI checks they match |
| Pool | `contracts/src/CordonPool.sol` | Immutable: tokens, note tree (depth 32), nullifiers, deposits with a 15-minute standby, withdrawals |
| Engines | `BundleVerifier`, `DvPSettler`, `EncumbranceRegistry` | Verify a proof, then ask the pool to spend/create notes (`applyOp`) |
| Index | `ActionEngine` | Turns multiplier changes (reinvested dividends) into an income index; holds unexplained jumps |
| Governance | `CordonControl`, `AssetGate`, `PriceOracle`, `NavAttestor`, TimelockController (24h) | Roles, listings, feeds, vaults |
| Checks | `SolvencyVerifier`, `ScreeningGate` | Hourly balance ≥ owed + fees; deposit screening in standby |
| Staking | `CrdnStaking` (not deployed) | Splits pool fees 80% workers (proving, relaying, registration) / 10% treasury / 5% stakers / 5% CRDN buyback-and-burn; each stake sweeps and distributes pool fees first |
| SDK | `packages/sdk` | Note model, tree, browser prover, builders, sealed boxes, DvP matcher |
| App | `src/` (TanStack Start on Vercel) | Dashboard; tRPC API in `src/server/trpc`; hosted testnet sequencer `src/server/sequencer.ts` |
| Workers | `supabase/functions` | indexer, relayer (user relays + keeper queue), clearer, action-watcher, solvency, encumbrance-keeper, vault-registrar (testnet), monitor |
| Database | `supabase/migrations` | Indexed public data, encrypted workspace backups, sealed inbox and orders; RLS everywhere |
| Enclave sequencer | `services/tee-sequencer` | Mainnet DvP sequencer in an AWS Nitro Enclave (not deployed) |

## Actors and roles

| Actor | Can | Cannot |
|---|---|---|
| User (note owner) | Deposit, send, split, bundle, claim income, encumber, place orders, withdraw | Spend another key's notes |
| Pledge / lien holder | Release (with a secret only it can compute), request a default, enforce after a declared default | Take a note before a default |
| Sequencer | Pair orders, choose the batch, prove and submit trades | Change any order term (bound by the trader's own order proof), spend notes outside orders, keep a trader's new notes (they rebuild them from the chain) |
| Keeper | Schedule splits, confirm index steps, pause income (≤3 days), flag deposits, declare defaults | Move funds, block exits |
| Guardian | Pause deposits / bundle / DvP / encumber | Pause exits |
| Governance (Safe → 24h timelock) | Engines, roles, listings, feeds, vaults | Touch the pool's balances directly; change an asset's class or claim mask after listing |
| Relayer | Submit users' proof-carrying calls | Anything else (no role) |

The full list of privileged functions and key custody is in [SECURITY.md](../SECURITY.md).

## Trust assumptions

- **Proof system:** Noir circuits and the bb UltraHonk verifiers are sound, and the
  universal SRS is honest.
- **Issuer (Robinhood Stock Tokens):** honest `uiMultiplier` / `newUIMultiplier` /
  `effectiveAt`. The pool must stay on the issuer's allow-list. A forced transfer out of
  the pool is not socialised; `SolvencyVerifier` makes it visible.
- **Oracles (Chainlink):** honest prices within the heartbeat (at most 1 day). DvP and NAV
  fail closed on stale feeds or a round older than the latest corporate action; nothing
  on the exit path reads prices.
- **Keeper:** live and honest for splits (`StepHeld` alerts) and defaults (PLEDGE / LIEN
  holders depend on it to declare a default).
- **Sequencer:** live; on testnet it can read orders (no enclave). It cannot steal or
  redirect funds.
- **Governance:** a 2-of-3 Safe behind a 24h timelock (testnet: one admin key).
- **Supabase / Vercel:** store only ciphertext and public chain data; they can censor or
  delay relays and orders, not move funds.

## Main flows

1. **Deposit → note:** `deposit` records the note commitment computed on-chain; after the
   15-minute standby anyone calls `clear` to insert it. Until then only the depositor can
   take it back (`unshieldToOrigin`).
2. **Private send / split / withdraw:** `transact` with a transfer proof (2 in, 2 out).
   Empty outputs take no leaf; a withdrawal names the recipient inside the proof.
3. **Bundle / income / unbundle:** a note splits into claims at the current index;
   INCOME pays `raw * (j_start - j_end) / j_bundle`; unbundle recombines at the index in
   force at the proof time.
4. **Encumbrance:** the holder hands the owner a pledge code (its key + the hash of a
   release secret only it can derive). Release before default, or enforce after one;
   every output blinding is derived from the encumbrance, so nobody can make the other
   side's note unspendable.
5. **DvP:** each trader proves its order (notes, amounts, wanted asset/class, minimum
   received, receive key, expiry) in its own browser and seals it to the sequencer. The
   sequencer proves the trade against both order hashes; the settler checks all three
   proofs and emits the masked amounts, from which each trader rebuilds its new notes.
6. **NAV:** a vault manager proves the value of its notes at the latest oracle rounds.
